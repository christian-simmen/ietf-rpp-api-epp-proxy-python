# Plan: container deployment on Ubuntu with Ansible

Branch `feature/184-deploy-ansible`, from `feature/177-sqlite-demo-backend` (the SQLite backend is not on `main` yet).
The draft PR targets `feature/177-sqlite-demo-backend` so that its diff is this work only; once #177 merges, the branch
is rebased onto `main` and the PR retargeted. Issue #184. Every commit is pushed to the draft PR.

## Goal

Deploy the proxy as containers on an Ubuntu host with Ansible:

- installed as an unprivileged user, on rootless Docker
- a hardened image
- 3 uvicorn workers per instance
- one instance per configuration, each on its own port: `epp`, `sqlite-demo`, `rri-mtest`
- SQLite on a bind-mounted directory, written by the 3 workers of its instance
- the EPP test server (pawel-kow/EPP-server-docker) deployed too, as the backend of the `epp` instance
- `rri-mtest` passes the client's credentials through to DENIC MTEST
- TLS terminated outside, by an nginx container on the root Docker daemon

## Decisions

- D1 Base: `feature/177` HEAD (maintainer, 2026-11-16).
- D2 The EPP server is internal only: no published ports, reached by the `epp` instance on the shared rootless network.
- D3 The proxy ports are published on the root daemon's bridge gateway (default: the address of `docker0`); nginx
  reaches them as `host.docker.internal` with `host-gateway`. The rootless and root daemons share no network.
- D4 Images are built on the host from git refs of this repository and of EPP-server-docker; no registry.
- D5 New top-level directory `deploy/` (`docker/`, `ansible/`); `.docker/Dockerfile` stays for development.

- D6 Instances are data, not code: `rpp_proxy_instances` in the inventory is a list of `{name, port, config, sqlite?,
  epp_backend?}`, where `config` is the proxy configuration as YAML (inline mapping or a file). The compose file, the
  config files and the data directories are generated by looping over it, so a new instance is one more list entry and
  needs no change to roles or templates (maintainer, 2026-11-16).
- D7 Draft PR opened early; every commit pushed (maintainer, 2026-11-16).

- D8 The role looks before it changes (maintainer, 2026-11-16, after a real host failed on its existing Docker
  repository): a preflight (`--tags preflight`, read only) reports packages, repositories, the root daemon, every
  user's rootless daemon, the deployment user's daemon.json and the AppArmor profiles; the role adopts what it did not
  make (daemon.json without its marker, another rootlesskit profile, an existing repository) and never changes another
  user's daemon. The deployment uses its own user `rpp` beside the host's other rootless Docker (maintainer).

## Findings

- `SqliteDatabase` serialises with a `threading.RLock`, which does not cover 3 worker processes; `migrate()` runs in
  every worker at start and would race on `create_all`.
- Reproduced before the fix (`tests/unit/test_sqlite_database_processes.py`): 6 processes doing 25 read-then-write
  units of work each ended at 25, not 150, with no error: pysqlite begins only at the first write, so the read ran
  outside the transaction. The startup race failed about 1 in 6 runs; after the fix, switching a new file to WAL still
  failed with "database is locked" without the busy timeout (SQLite does not wait there), hence the retry in
  `_write_ahead`. After the fix: 0 failures in 30 runs.
- Security known debt #14 (`TCPClient` prints sent EPP messages, the login `<pw>` included) means the `epp` instance's
  container log holds registrar passwords; the deployment caps and rotates logs, but does not fix it.
- EPP-server-docker publishes ports under 1024 (43, 443); under rootless Docker these fail, hence D2.

- Image check (devcontainer, docker outside of docker): read-only root, `cap_drop ALL`, no-new-privileges, UID 10001,
  3 workers, healthy after about a minute (each worker builds the app from openapi.yaml), about 360 MiB with 3 workers.
  60 concurrent planet creates against a file in `/data` stored 60 rows. The discovery healthcheck needs `RPP-Cltrid`.
- uvicorn restarts a worker that dies (e.g. a bad config), so the container stays up and turns `unhealthy`; Docker does
  not restart unhealthy containers, so the role waits for `healthy` after a deploy and fails otherwise.

- Test host: a privileged Ubuntu 24.04 container with systemd (scratchpad), Ansible run inside it (the docker
  connection plugin loses the output of long modules through docker-outside-of-docker). Not covered there: the AppArmor
  profile (loading it would change the real host kernel's policy; `rootless_docker_apparmor_profile: false`), nginx as
  a container of the root daemon (that daemon cannot run containers in the test host; requests came from the host on
  the docker0 address instead), ufw. `rootless_docker_dns` was set: the outer resolver (Colima, 192.168.5.2) drops
  parallel A/AAAA queries, as EPP-server-docker notes.
- Results on the test host: full run ok=45 failed=0; second run changed=0; 3 instances healthy, read-only, cap_drop
  ALL, no-new-privileges, UID 10001, 3 workers, ports only on docker0's address; discovery 200 on 8091-8093; epp:
  availability 200 `01000` through epp-server:743, wrong password 401 `02200`; sqlite: 90 concurrent creates, 90 rows,
  files owned by subuid 175536 = 165536 + 10001 - 1; a 4th instance from an inline `config` came up with 2 workers,
  a changed base_url recreated rri-mtest only, removing the entry removed the container and kept its directory.
- Checks: lint-imports 25 kept; unit 2687 passed; smoke 94 passed, 113 skipped; ansible-lint production profile, 0
  failures; syntax-check ok.
- Not fixed: requirements.txt holds the test packages next to the runtime ones (#191); the image uninstalls them.

- Final checks (2026-11-17): lint-imports 25 kept; unit 2687 passed; smoke 94 passed, 113 skipped; ansible-lint
  production profile, 0 failures.
